# Alignment & Test Convergence Guide

This guide documents the two iterative convergence loops that `project-orchestrator` runs for **every** project generated by the Azure Architecture Factory (AAFactory), greenfield or update:

1. **Phase 2.5 — Alignment Convergence Loop** — proves BRD ↔ architecture diagram ↔ source code ↔ infrastructure are in sync.
2. **Phase 3.7 — Test Convergence Loop** — proves every component, NFR, and infra resource from Phase 2.5 has executable test coverage and the suite is green.

Both loops are **mandatory** and each runs a **minimum of 3 iterations**. They cannot be skipped except via an explicit governance override (`skip-alignment: true`), which is logged as an exception.

---

## Why Two Loops

Historical AAFactory runs produced projects where:
- BRD requirements were present in the diagram but missing from `src/` (or vice versa).
- NFRs (rate limits, auth, audit logging) appeared in the BRD and diagram notes but existed only as TODO comments in code.
- Tests covered happy paths but not the Bicep resources or NFRs.
- Documentation (`README.md`, `DEPLOY.md`) referenced services that were never implemented.

A single drift-check pass missed late-binding gaps: fixing one gap often exposed another. A fixed number of iterations with a convergence criterion closes the loop.

## Phase 2.5 — Alignment Convergence Loop

### Participants

| Agent | Mode | Responsibility |
|-------|------|---------------|
| `brd-to-architecture-diagram` | `extract-inventory` | Parse the BRD into a canonical JSON inventory (services, data stores, integrations, flows, NFRs, compliance). |
| `drawio-architecture-reader` | `inventory` | Extract the current diagram's component/flow inventory as canonical JSON. |
| `source-code-maintainer` | `inventory` | Extract the current `src/` + `infra/` inventory as canonical JSON. |
| `brd-to-architecture-diagram` | `update` | Apply diagram deltas when the BRD has required components the diagram lacks. |
| `azure-architecture-implementer` | `incremental` | Apply code/infra deltas for components and NFRs the code lacks. Materialize NFRs as executable code, not comments. |
| `source-code-maintainer` | `refactor` | Handle code-only changes (renames, moved responsibilities, contract updates). |

### Per-Iteration Protocol

For iteration `N` (1..5):

1. **BRD inventory** → `projects/<slug>/docs/alignment/brd-inventory-iter-N.json`
2. **Diagram inventory** → `projects/<slug>/docs/alignment/diagram-inventory-iter-N.json`
3. **Code inventory** → `projects/<slug>/docs/alignment/code-inventory-iter-N.json`
4. **Orchestrator computes 3-way diff** and classifies gaps:
   - `missing_from_diagram` — in BRD, not in diagram
   - `missing_from_code` — in BRD and diagram, not in code/infra
   - `orphaned_in_code` — in code, not in BRD or diagram (flagged for human review, NOT auto-deleted)
   - `nfr_gaps` — NFR in BRD has no implementation hook in code
5. **Delegate fixes** to the responsible agent per the Participants table.
6. **Hand off test impact** to Phase 3.7: `projects/<slug>/docs/alignment/test-impact-iter-N.json` lists every component and NFR added or modified this iteration.
7. **Write iteration report** → `projects/<slug>/docs/alignment/alignment-report-iter-N.md`

### Exit Conditions

| Condition | Status | Action |
|-----------|--------|--------|
| `N ≥ 3` AND two consecutive iterations report zero gaps | `converged` | Proceed to Phase 3. |
| `N == 5` AND any gap remains | `unresolved` | Halt. Escalate the remaining gaps to the caller. Resume only with `force: true`. |
| Gap count non-decreasing across 2 iterations | `stalled` | Halt. Escalate with the last recorded error per gap. |

### Outputs

```
projects/<slug>/docs/alignment/
├── brd-inventory-iter-1.json
├── diagram-inventory-iter-1.json
├── code-inventory-iter-1.json
├── test-impact-iter-1.json
├── alignment-report-iter-1.md
├── ... (N iterations)
└── alignment-report.md           # final synthesis
```

Manifest: `project-manifest.json → phases.2_5_alignment_convergence`.

Log line: `[PHASE 2.5] Alignment iteration N/5 → gaps_found: X (diagram: Y, code: Z, nfr: W)`

## Phase 3.7 — Test Convergence Loop

### Participants

| Agent | Mode | Responsibility |
|-------|------|---------------|
| `azure-architecture-implementer` | `generate-tests` | Generate pytest cases per service, NFR, and Bicep resource from `test-impact-iter-N.json`. |
| `source-code-maintainer` | `refactor` | Fix code defects surfaced by failing tests without weakening the assertion. |
| `bicep-infrastructure-validator` | (default) | Fix infra defects surfaced by what-if or policy test failures. |
| `azure-architecture-implementer` | `fix-tests` | Adjust tests ONLY when a failure is classified as a test defect (assertion wrong, selector wrong). Must cross-check against Phase 2.5 inventories. |

### Per-Iteration Protocol

For iteration `N` (1..5):

1. Load `docs/alignment/test-impact-iter-*.json`.
2. Generate/update tests for listed components, NFRs, and resources.
3. Run the full suite:
   ```
   python -m pytest projects/<slug>/tests -v --tb=short --no-header \
     --junitxml=projects/<slug>/logs/test-results-iter-N.xml
   ```
4. Classify each failure as **code defect**, **infra defect**, or **test defect** and delegate the fix.
5. Write `docs/test-convergence/test-report-iter-N.md`.
6. Append to `docs/test-convergence/coverage-log.md`.

### Exit Conditions

| Condition | Status |
|-----------|--------|
| `N ≥ 3` AND two consecutive iterations pass with 0 failures | `converged` |
| `N == 5` AND failures remain | `unresolved` — halt before Phase 4 |
| Test passes in iteration `N-1` and fails in `N` with no code change | Mark as **flaky**, quarantine, continue |

Manifest: `project-manifest.json → phases.3_7_test_convergence`.

Log line: `[PHASE 3.7] Test iteration N/5 → cases: X (new: Y, updated: Z), failures: W`

## Governance

- Both loops are **non-optional** for every factory-generated project and every BRD update cycle.
- `skip-alignment: true` is the only bypass and must be logged in `logs/orchestration.log` as a governance exception with the caller's name.
- `force: true` after an `unresolved` exit is permitted but logs the unresolved gaps to the final `alignment-report.md` / `coverage-log.md` so future audits can trace the decision.
- Orphaned code (`orphaned_in_code`) is **never** auto-deleted. It is surfaced as a human-review finding because it may represent a legitimate architectural improvement that predates the BRD.

## Troubleshooting Stalls

| Symptom | Likely Cause | Remediation |
|---------|-------------|-------------|
| Same `missing_from_code` gap every iteration | Implementer cannot resolve a component name to a package | Check naming convention in `docs/alignment/code-inventory-iter-N.json`; rename in diagram or code to match. |
| `nfr_gaps` never reaches zero | NFR asserted in BRD but no template exists | Provide a reference implementation in `factory-templates/` and re-run. |
| Test convergence flaps | Non-deterministic test (time, network, randomness) | Quarantine, add to `docs/test-convergence/flaky-tests.md`, fix with a seeded fixture. |
| 3-way diff explodes after one fix | A service rename propagated incorrectly | Roll back to the iteration-N-1 snapshot under `diagrams/history/` and re-apply fix scoped to one service. |
