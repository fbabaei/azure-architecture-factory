# Casewright — Retrieval Design (`azure_ai_search`)

Generated by `knowledge-retrieval-architect` (mode: design → scaffold). Machine-readable
contract: [retrieval-design.json](./retrieval-design.json).

## Pattern decision

| Condition (first match wins) | Result |
|---|---|
| Corpus already in SharePoint + Blob, needs metadata/provenance filtering, incremental sync, multimodal enrichment | **`azure_ai_search`** ✅ |

`file_search` was rejected: it cannot do incremental sync, metadata filtering, or multimodal
enrichment, all of which the BRD requires.

## Pull-model resources

- **Data source** — Azure Blob, change detection `HighWaterMark` on
  `metadata_storage_last_modified`, deletion detection `SoftDelete` on an `is_deleted`
  marker. Auth = managed identity (`ResourceId=`), no connection-string key.
- **Index** — `casewright-index`. Key `content_id`; text `content_text`; vector
  `content_embedding` (HNSW + scalar quantization, Azure OpenAI vectorizer); metadata
  `document_title`, `source_path`, `site_id`, `content_type`, `last_modified`; semantic
  config over title + content.
- **Skillsets** — three:
  - **multimodal** (binary): layout extract → split → embed; image verbalize → image embed;
    index projections (text vs image nodes) + knowledge store (extracted images to Blob).
  - **markdown**: split → embed.
  - **json**: split → embed.
- **Indexers** — one per skillset path, all projecting into `casewright-index`. Run
  **on-demand**, triggered by the worker only when `added + updated + deleted > 0`.

## Chunking & embedding
Characters, `maximum_length = 3000`, `overlap = 500`. Embedding deployment + dimensions read
from `Settings` (`embedding_deployment`, `embedding_dimensions`) — never hardcoded.

## Query
Hybrid (vector + keyword) → semantic reranker → drop matches below `min_reranker_score`
(default `2.0`) → return ranked chunks with citation metadata (`document_title`,
`source_path`).
